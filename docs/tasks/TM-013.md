# TM-013: Investment configuration editing screen

## Goal

The operator edits the investment configuration's order amount, limit price tolerance, and authorized analytics applications. Every change is audited and affects only trade signals evaluated afterwards.

## Scope

In scope:

- A Livewire screen in the protected panel from TM-010.
- The edit application commands and the aggregate's change behavior.
- A read-only Eloquent read model for display ([ADR-0004](../ADR/adr-0004-livewire-eloquent-read-models.md)).
- Browser tests of the screen ([testing strategy](../testing-strategy.md#browser-tests-with-playwright)), with seeded data for them.

Out of scope:

- Changing the currency or the brokerage account.
- Creating investment configurations.
- Editing the registry of analytics applications, which is deployment-time configuration.

## Requirements

### Screen

- It shows the reference, currency, and brokerage account as read-only.
- The panel navigation gets an Investment configuration entry, which links to this screen. It follows the mockup's order: after Start, and after Orders when that entry exists.

### Editable fields

- Order amount: Money greater than zero, in the investment configuration's currency, with at most two decimal places.
- Limit price tolerance: from 0 % to 5 % inclusive.
- Authorized analytics applications: chosen from the registry of known analytics applications.

### Saving

- On invalid input, the screen shows validation errors and saves nothing. The aggregate enforces the same rules without the GUI.
- An optimistic version check refuses a save made from stale data.
- The audit trail records each changed field with the operator, the time, the old value, and the new value.

### Effect of a change

- Changes apply only to trade signals evaluated afterwards.
- Existing orders keep their settings snapshot.
- Removing an analytics application leads to `SignalRejected` for its later trade signals at intake, and does not affect existing orders.

### Visual design

The screen follows [`investment-configuration.html`](../gui-design/investment-configuration.html), and its validation errors follow [`investment-configuration-errors.html`](../gui-design/investment-configuration-errors.html). Both are built from the design system of TM-010 in both themes. Elements that the mockup shows but this task does not require are not built.

### Access

- Screen actions use CSRF protection and are available only to the authenticated operator.

### Browser tests

- A seeder in `src/Trading/Infrastructure/`, which `bin/e2e` runs after `BrowserTestOperatorSeeder`, creates through the application's use cases the investment configuration `demo-eur` with the brokerage account `DEMO-ACC-001`, an order amount of 200.00 EUR, a limit price tolerance of 0.50 %, and the authorized analytics application `demo-analytics`, as `investment-configuration.html` shows it. When TM-011 is on `main`, its seeder already does this; otherwise this task adds the seeder with the investment configuration only, and TM-011 extends it.
- The registry of the e2e application holds `demo-analytics` and `demo-analytics-2`, set through `TRADING_ANALYTICS_APPLICATIONS` on `e2e-app` in `compose.yaml`.
- The mockup comparisons use `expectToMatchMockup` element by element, in the elements this task requires, because the mockup pages also show elements of other tasks.
- Tests that change the investment configuration run in a Playwright project after the other panel tests and before the logout test.

## Decisions

- The look of the screen and its validation errors are checked by this task's browser tests, not by a manual check ([testing strategy](../testing-strategy.md#browser-tests-with-playwright)). The manual check keeps the change's effect on trade signals from the demo analytics application. The owner decided this on 2026-11-26.

## Constraints

- A change to `bin/e2e` or `compose.yaml` follows [SDLC §6](../../SDLC.md#changes-to-ci-configuration).

## Acceptance criteria

- [ ] Behat: with a reference price of 10.00 EUR, an order amount of 1000.00 EUR, and a tolerance of 2 %, an order awaiting approval has a limit price of 10.20 EUR and a quantity of 98. After the order amount changes to 2000.00 EUR and the tolerance to 1 %:
  - that order keeps 10.20 EUR and 98;
  - a trade signal with the same reference price evaluated after the change creates an order with a limit price of 10.10 EUR and a quantity of 198.
- [ ] Behat: after an analytics application is removed, its next trade signal ends with `SignalRejected`.
- [ ] Domain unit tests cover the edit rules and the unchangeable currency and brokerage account:
  - tolerance: 0 % and 5 % accepted, -0.01 % and 5.01 % rejected;
  - order amount: 0.01 EUR accepted; zero, a negative amount, another currency, and three decimal places rejected;
  - analytics applications: only applications from the registry accepted.
- [ ] PostgreSQL test: a save based on a stale version is refused without changes or audit records.
- [ ] PostgreSQL test: a write through the read model throws an exception and changes nothing.
- [ ] Feature test: the panel navigation contains the Investment configuration entry, which links to the screen, after Start and after Orders when that entry exists.
- [ ] Feature tests:
  - validation errors are shown;
  - each action invokes the intended command;
  - authentication and CSRF are required.
- [ ] PHPUnit application test: each change produces audit records with the operator, the time, and the old and new values.
- [ ] Feature test: the seeder creates the investment configuration with the values listed under Browser tests.
- [ ] Browser test: the page title, the read-only values, the editable fields with their values, the authorized analytics applications, and the Save changes button match `investment-configuration.html`, and the Investment configuration navigation entry on the application's start page matches the one in `start.html`, in both themes, with at most 1% of the pixels differing.
- [ ] Browser test: saving an order amount of 0.00 EUR and a limit price tolerance of 7.50 % shows field errors that match `investment-configuration-errors.html` in both themes, and after a reload the screen shows the seeded values.
- [ ] Browser test: after a save in one page, a save from a second page opened before it shows the message that the investment configuration changed, which matches `investment-configuration-errors.html` in both themes, and after a reload the screen shows the values of the first save.
- [ ] A manual check in the local environment is described in the PR: with an order for `DEMO_A` awaiting approval at a reference price of 10.00 EUR, an order amount of 1000.00 EUR, and a tolerance of 2 % (10.20 EUR, quantity 98), the operator changes the order amount to 2000.00 EUR and the tolerance to 1 % on the screen. The next trade signal for `DEMO_A` at 10.00 EUR from the demo analytics application (TM-006) creates an order at 10.10 EUR with a quantity of 198, and the existing order keeps 10.20 EUR and 98.
