# TM-013: Investment configuration editing screen

## Goal

The operator edits the investment configuration's order amount, limit price tolerance, and authorized analytics applications. Every change is audited and affects only trade signals evaluated afterwards.

## Scope

In scope:

- A Livewire screen in the protected panel from TM-010.
- The edit application commands and the aggregate's change behavior.
- A read-only Eloquent read model for display ([ADR-0004](../ADR/adr-0004-livewire-eloquent-read-models.md)).

Out of scope:

- Changing the currency or the brokerage account.
- Creating investment configurations.
- Editing the registry of analytics applications, which is deployment-time configuration.

## Requirements

### Screen

- It shows the reference, currency, and brokerage account as read-only.

### Editable fields

- Order amount: Money greater than zero, in the investment configuration's currency, with at most two decimal places.
- Limit price tolerance: from 0 % to 5 % inclusive.
- Authorized analytics applications: chosen from the registry of known analytics applications.

### Saving

- On invalid input, the screen shows validation errors and saves nothing. The aggregate enforces the same rules without the GUI.
- An optimistic version check refuses a save made from stale data.
- The audit trail records each changed field with the operator, the time, the old value, and the new value.

### Effect of a change

- Changes apply only to trade signals evaluated afterwards.
- Existing orders keep their settings snapshot.
- Removing an analytics application leads to `SignalRejected` for its later trade signals at intake, and does not affect existing orders.

### Access

- Screen actions use CSRF protection and are available only to the authenticated operator.

## Acceptance criteria

- [ ] Behat: with a reference price of 10.00 EUR, an order amount of 1000.00 EUR, and a tolerance of 2 %, an order awaiting approval has a limit price of 10.20 EUR and a quantity of 98. After the order amount changes to 2000.00 EUR and the tolerance to 1 %:
  - that order keeps 10.20 EUR and 98;
  - a trade signal with the same reference price evaluated after the change creates an order with a limit price of 10.10 EUR and a quantity of 198.
- [ ] Behat: after an analytics application is removed, its next trade signal ends with `SignalRejected`.
- [ ] Domain unit tests cover the edit rules and the unchangeable currency and brokerage account:
  - tolerance: 0 % and 5 % accepted, values just outside rejected;
  - order amount: 0.01 EUR accepted; zero, a negative amount, another currency, and three decimal places rejected;
  - analytics applications: only applications from the registry accepted.
- [ ] PostgreSQL test: a save based on a stale version is refused without changes or audit records.
- [ ] PostgreSQL test: a write through the read model throws an exception and changes nothing.
- [ ] Feature tests:
  - validation errors are shown;
  - each action invokes the intended command;
  - authentication and CSRF are required.
- [ ] PHPUnit application test: each change produces audit records with the operator, the time, and the old and new values.
- [ ] A manual check in the local environment is described in the PR: with an order for `DEMO_A` awaiting approval at a reference price of 10.00 EUR, an order amount of 1000.00 EUR, and a tolerance of 2 % (10.20 EUR, quantity 98), the operator changes the order amount to 2000.00 EUR and the tolerance to 1 % on the screen. The next trade signal for `DEMO_A` at 10.00 EUR from the demo analytics application (TM-006) creates an order at 10.10 EUR with a quantity of 198, and the existing order keeps 10.20 EUR and 98.
- [ ] `CI_WITH_MUTATION=diff make ci` passes.
