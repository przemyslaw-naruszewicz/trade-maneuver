# TM-001: Trading context foundation

## Goal

Prepare the source layout and quality gates for the Trading bounded context, so that later tasks add business behavior without reconfiguring tooling. This is prefactoring: it adds no business behavior.

## Scope

In scope:

- The PSR-4 mapping `TradeManeuver\` → `src/` next to the existing `App\` mapping, as described in [architecture.md](../architecture.md#laravel-integration).
- The Trading context with the four layers `Domain`, `Application`, `Infrastructure`, and `Ui`, following the target layout. Create only the elements needed now: the context service provider, registered in the application's provider list, that merges the context configuration and loads the context migration directory.
- Deptrac rules for the Trading layers and for the remaining application-owned code under the root namespace.
- The PHPStan extension `spaze/phpstan-disallowed-calls`, configured to reject calls from `Domain` and `Application` to functions defined in installed packages.
- Coverage and analysis paths: PHPUnit source coverage, Infection source directories, and PHPStan paths include `src/`.
- The pull-request mutation check: PR CI runs Infection on the lines a PR changes, with a local equivalent.
- Terminology fix: the health-check Behat feature and step say "Trade Maneuver" instead of "execution service" ([dictionary](../dictionary.md): Trade Maneuver is the name; "execution service" only describes its role).
- Updates to the documentation that says Deptrac has an empty ruleset (README, architecture, testing strategy), so that it describes the enforced rules and the PHPStan check. This includes the architecture's rule on how layer boundaries are enforced.
- Updates to the statements about PR CI and Infection (README, SDLC §6, testing strategy), so that they describe the current checks.

Out of scope:

- Any domain model, use case, persistence, messaging, or GUI.
- New dependencies other than `spaze/phpstan-disallowed-calls`.

## Requirements

Deptrac must reject each forbidden direction from [architecture.md](../architecture.md#directory-structure-and-layers) in these common forms: `extends`, `implements` on a class, trait use, `new`, static calls, class constants, and native parameter, return, and property types. It must also reject them in fully qualified or imported calls to the project's own functions:

- `Domain` depends on no other layer and on no framework or infrastructure package (Laravel, Eloquent, Symfony components, AMQP clients). The task that adopts an approved library, such as the Money library, also allows it in `Domain`.
- `Application` depends only on `Domain` and on no framework package.
- `Ui` and `Infrastructure` may depend on `Application` and `Domain`; `Ui` must not depend on `Infrastructure`.
- Composition-root registration in the context service provider may reference concrete adapters and `Ui` classes; ordinary adapter code may not use that exception.

PHPStan must reject a call from `Domain` or `Application` to a function defined in an installed package, in these forms: unqualified, fully qualified, imported with `use function`, and as a first-class callable. PHP's own functions and the project's own functions stay allowed, and `Infrastructure` and `Ui` may call package functions. A call in a trait belongs to the layer that defines the trait, wherever the trait is used.

`CI_WITH_MUTATION=diff make ci` runs the pull-request checks plus Infection on changed lines:

- The Infection run uses `--git-diff-lines --git-diff-base=origin/main --ignore-msi-with-no-mutations`, leaves out `--with-uncovered`, and keeps the configured thresholds.
- PR CI uses this variant, and its checkout fetches enough history to find the merge base with `origin/main`.
- Pushes to `main` and manual dispatch keep the full Infection run. `CI_WITH_MUTATION=0` and `CI_WITH_MUTATION=1` keep their meaning.

## Decisions

- The owner decided on 2026-11-03 to add Infection on changed lines to PR CI once `src/` is part of Infection's sources. Approving this task approves that CI change ([SDLC §6](../../SDLC.md#6-ci)).
- Deptrac 4.7.2 cannot resolve an unqualified function name inside a namespace, which is how Laravel helpers such as `config()` and `now()` are normally called. The owner decided on 2026-11-04 to check package functions with the MIT-licensed PHPStan extension `spaze/phpstan-disallowed-calls`, because PHPStan's reflection resolves the name and configuration needs no custom rule, tests, or fixtures. Approving this task approves this new development dependency. Deptrac analyses no `vendor/` files, so that this problem has one check ([architecture](../architecture.md#consistency-and-simplicity)).
- The check is one `disallowedFunctionCalls` entry in `phpstan.neon.dist`: `function: '*'`, `definedIn` `vendor/*`, and `allowExceptIn` `src/*/Domain/*` and `src/*/Application/*`, with `filesRootDir` set to the project root. This was checked on version 4.15.0 with PHPStan 2.3.2 on 2026-11-04, in a scratch clone.
- The owner accepted these known gaps in the checks on 2026-11-04:
  - Neither tool detects a global function of the project called unqualified from another layer. The project defines no functions today.
  - The PHPStan check does not report a callable whose name PHPStan cannot determine, such as `$callable()` on a `callable` parameter.
  - No committed test covers the check's configuration, so a package upgrade that changes its behavior would not fail CI.
- The owner decided on 2026-11-05 to verify Deptrac on the common forms listed in Requirements. Review covers the forms Deptrac does not detect and classes from PHP extensions, which its `php_internal` collector treats as PHP's own. This task does not list those cases.
- These flags were checked on Infection 0.35.8 on 2026-11-03, in a scratch clone with the thresholds unchanged. Without `--ignore-msi-with-no-mutations`, a comment-only PHP change fails at 0 % MSI. With `--with-uncovered`, a line PHPUnit does not run fails at 0 % MSI, which would also hit code that only Behat exercises.

## Constraints

- Follow the CI change process ([SDLC §6](../../SDLC.md#changes-to-ci-configuration)):
  1. `make ci-lint`;
  2. run the affected CI variant locally;
  3. check the GitHub Actions run.
- Infection fails when it generates no mutations. The existing `app/` code keeps it non-empty; adding an empty `src/` must not break PHPUnit, PHPStan, Deptrac, or Infection.
- Registration must work with cached configuration and routes.
- No dependency changes other than adding `spaze/phpstan-disallowed-calls` as a development dependency.

## Acceptance criteria

- [ ] Feature test: a class in the `TradeManeuver\Trading\…` namespace under `src/` autoloads in the application and in tests.
- [ ] Feature test: the Trading service provider is registered. The PR shows the application booting with `config:cache` and `route:cache` applied.
- [ ] Deptrac fails for each forbidden direction in the common forms listed in Requirements and in fully qualified or imported calls to the project's own functions, and passes for the allowed ones. The PR shows the output of one temporary violating class per forbidden direction, using those forms. The classes are not committed.
- [ ] `composer analyse` fails on temporary classes that call package functions, including `config()` and `now()`, from `Domain` in each form listed in Requirements, from `Application` in the unqualified form, and from a `Domain` trait used in `Infrastructure`. It reports nothing for temporary classes that call PHP's own functions or the project's own functions, that call package functions from `Infrastructure` and `Ui`, or that use an `Infrastructure` trait in `Domain`. It passes without the classes. The PR shows the output; the classes are not committed.
- [ ] PHPUnit source coverage, Infection source directories, and PHPStan paths include `src/`.
- [ ] The health-check Behat scenario uses "Trade Maneuver" and still passes.
- [ ] README, architecture, and testing-strategy statements about Deptrac and the PHPStan check match the enforced rules.
- [ ] README, SDLC §6, and testing-strategy statements about PR CI and Infection match the new check and no longer call it planned.
- [ ] The PR shows `CI_WITH_MUTATION=diff make ci` output for temporary changes, which are not committed: no source change passes; a comment-only change passes; a changed line whose test lets a mutant survive fails; the same line with a test that kills the mutant passes.
- [ ] The GitHub Actions run on the PR includes Infection on changed lines. The workflow keeps the full Infection run for pushes to `main` and manual dispatch.
- [ ] `CI_WITH_MUTATION=0 make ci`, `CI_WITH_MUTATION=diff make ci`, and `make ci` pass.
